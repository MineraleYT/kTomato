# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

kTomato is a Pomodoro timer for KDE Plasma 6: C++17 + Qt 6.6+ / KDE Frameworks 6.8+ backend, Kirigami QML UI, local SQLite storage. `docs/DEVELOPMENT.md` is the authoritative dev guide (distro dependencies, Flatpak build, translating, release checklist).

## Commands

```sh
cmake -S . -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug -DBUILD_TESTING=ON
cmake --build build
ctest --test-dir build --output-on-failure              # whole suite
ctest --test-dir build -R tst_timerengine --output-on-failure   # one test (QtTest binaries also accept a test function name when run directly)

# Same conditions as CI (no display, no session bus):
env -i PATH=/usr/bin:/bin HOME=/tmp/ktomato-test-home ctest --test-dir build --output-on-failure

# Metadata validation (also run in CI)
appstreamcli validate --no-net data/io.github.mineraleyt.ktomato.metainfo.xml
desktop-file-validate data/io.github.mineraleyt.ktomato.desktop build/io.github.mineraleyt.ktomato.runner.desktop  # generated by configure

# Translations: regenerate po/ktomato.pot, then merge per language
bash po/Messages.sh
msgmerge --update --backup=none po/<lang>/ktomato.po po/ktomato.pot
```

The build must stay free of compiler warnings. There is no separate linter.

## Architecture

**Wiring lives in `src/main.cpp`.** It owns object lifetimes (declaration order is deliberate: database/repositories/inhibitor before the QML engine, helpers parented to a `services` QObject after it) and connects all services by signals. Several C++ classes are QML singletons (`QML_ELEMENT`/`QML_SINGLETON`: `TimerEngine`, `PresetModel`, `AppSettings`, `SilenceController`, `StatsModel`, `ScreenLockWatcher`, `Diagnostics`, `CalendarSync`); main fetches them via `engine.singletonInstance<>()` and then `attach()`es their dependencies, rather than constructing them itself. `DataManager` and `FocusSoundController` are exposed as context properties instead.

**Data flow centers on `TimerEngine`** (`src/core/TimerEngine.h` documents the full state machine). Remaining time is always `deadline - clock.now()` from an injectable `Clock` (monotonic), so ticks only drive UI refresh; tests use `tests/FakeClock.h`. Other components are observers of its signals:
- `TimerBinding` pushes the selected preset from `PresetModel` into the engine (switching preset resets; editing only reconfigures).
- `SessionRecorder` turns `sessionEnded` into rows via `SessionRepository`; `StatsModel`/`StatsAggregator` read them; `CalendarSync` listens for `workSessionRecorded` and uploads CalDAV events.
- `PhaseNotifier`, `SilenceController` (notification inhibit), `PowerInhibitor`, `ScreenLockWatcher`, `FocusSoundController`, `TrayController`/`TrayPresenter` react to state changes.
- External control: `DBusTimerService` adaptor at `/Timer`, `KRunnerService` at `/krunner`, both on the `io.github.mineraleyt.ktomato` bus name, which `SingleInstance` also uses to forward second launches.

**Persistence is split:** presets and sessions are in SQLite (`src/db/`, `~/.local/share/ktomato/ktomato.db`); app preferences are KConfig (`ktomatorc`, via `AppSettings`). The calendar password goes to the desktop keyring through `SecretStore` (Secret Service over D-Bus), with `ktomatorc` only as a fallback; `CalendarSync` keeps its unsent-event queue in `ktomatorc` too, each event bound to the account it was queued for. `Database` tags its files with `PRAGMA application_id`, versions the schema with `PRAGMA user_version` and an ordered `migrations()` list in `Database.cpp` (append new migrations; never edit old ones), moves foreign/corrupt files aside, and refuses newer schemas. A file it cannot read (busy, locked) is never moved: `open()` fails and `main.cpp` falls back to an in-memory database. Repositories hold only the connection *name*. If the file can't be opened the app falls back to an in-memory DB. `PresetPersistence` loads presets into the model and saves every change synchronously.

**Platform abstractions:** notification inhibition goes through `NotificationInhibitor` with `FreedesktopInhibitor`/`NoopInhibitor` chosen by `InhibitorFactory`; tests substitute `tests/FakeInhibitor.h`. Autostart is unavailable under Flatpak.

## Adding files and tests

- There is no internal library: `src/CMakeLists.txt` lists every source explicitly, and each test in `tests/CMakeLists.txt` compiles the specific `src/` `.cpp` files it needs. A new source file must be added to `src/CMakeLists.txt` **and** to every test target that (transitively) uses it, or tests fail to link. New QML files go in the `ecm_add_qml_module` `QML_FILES` list.
- A new test needs an `ecm_add_test(...)` entry and must be added to the `foreach(test ...)` include-directories list at the bottom of `tests/CMakeLists.txt`.
- Tests that create a GUI application set `QT_QPA_PLATFORM=offscreen` via `set_tests_properties`. D-Bus tests start a throw-away bus with `tests/PrivateDBus.h` (no service activation, so nothing installed on the machine is started) and must work (or skip) without a session bus.
- QML pages are covered by smoke runs (`tests/smoke_app.sh`): the real binary starts offscreen with `KTOMATO_SMOKE_PAGE=<page>` (or `KTOMATO_STATS_SMOKE_TEST=1`) and isolated XDG dirs; any QML warning fails the run (exit 30), and smoke-mode checks in `Main.qml` call `Qt.exit()` with a non-zero code on failure (e.g. 23-28 for the settings, welcome and timer-page checks). `tests/manual-review-checklist.md` covers what automation doesn't.

## Conventions

- User-visible strings use KI18n `i18n()` / `i18np()` for plurals, never `tr()`. Compile definitions forbid implicit ASCII casts (`QT_NO_CAST_FROM_ASCII` etc.): use `QStringLiteral`/`QLatin1String`.
- QML uses only `Kirigami.Theme` colours and `Kirigami.Units` sizes. `tests/check_qml_colours.sh` fails on any colour literal (only `"transparent"` is allowed); the tray icon's fixed colours live in `src/core/TrayIconStyle.h`, used by both `TrayController` and the welcome page's picture of the icon. `tests/check_qml_sizes.sh` fails on literal sizes of 2 px or more; allowed are 0/1 (no spacing, layout weights, 1 px borders) and artwork drawn in its own coordinates and scaled as a whole, between `// artwork-begin` and `// artwork-end`.
- Every file carries an SPDX header (GPL-3.0-or-later for code, CC-BY-SA-4.0 for docs).
- Adding a UI language: new `po/<lang>/ktomato.po`, plus the language lists in `src/core/AppSettings.cpp`, `src/qml/pages/AppSettingsPage.qml` and `src/qml/pages/WelcomePage.qml`; the `.desktop`, runner and `ktomato.notifyrc` files carry `Key[lang]=` translations.
- Releases: version must agree across `CMakeLists.txt` `project(... VERSION)`, the newest `<release>` in the metainfo XML, and the `vX.Y.Z` tag, or the release workflow refuses to publish. Follow the checklist in `docs/DEVELOPMENT.md`.

## Working with subagents

Subagents may be used for this repository. When spawning one, prefer the Haiku 5.5 model (`model: "haiku"`) unless the task clearly needs a stronger model.

Each Haiku 5.5 subagent has a budget of 100k tokens. The Agent tool has no hard token limit, so keep within it by:
- giving each subagent one narrow, well-scoped task, with the file paths it needs already in the prompt so it doesn't search broadly;
- telling it in the prompt that it must finish within 100k tokens, read only the parts of files it needs, and return a short answer;
- splitting larger work into several smaller subagents rather than one long-running one.
